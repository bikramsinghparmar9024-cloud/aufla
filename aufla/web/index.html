How a source gets onboarded

A mapping is a YAML file. Drop one into sources/ and the next event from that source normalises — no restart, no code change, no redeploy.

The same file is what the AI lane produces. For a format nobody recognises, Drain3 mines the template and a grammar-constrained local model proposes a mapping; deterministic checks score it and an analyst approves it. Human and machine author the identical artifact, so every automated decision stays reviewable, diffable and version-controlled.

Unknown OCSF targets, unknown classes, duplicate rule names and shadowing catch-all rules are all rejected at load — whoever wrote the file.

What the chain seals

The raw stream. The OCSF projection is rebuildable and therefore mutable by design, so it is not the evidence — the original bytes are.

Each batch commits the hashes of the mappings in force, so for any normalised row you can prove which raw event produced it, under which mapping version, and that neither has changed.

Batch roots are signed with an online key; a daily checkpoint is signed with an offline key, bounding forgery to a single day if the online key is stolen.
