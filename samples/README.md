# Sample log data

Three kinds of sample, kept separate because they serve different purposes and
have different provenance.

## `live/` — format-faithful samples of services that run in Docker

Generated by `tools/make_samples.py` to match exactly what each product emits,
including the awkward parts that break naive parsers:

- Zeek's tab-separated `conn.log` **with its `#fields` header block**
- nginx combined format, where the request line, referrer and user agent are
  quoted strings containing spaces
- auditd's nested `msg='...'` quoting inside a key-value record
- OpenSSH's optional `invalid user` insertion, which only appears for accounts
  that do not exist

These let the parsers and mappings be developed and tested without needing
every one of those products installed. `docker/` runs the real services; these
are what make the pipeline testable when those are not up.

## `replay/` — vendor formats replayed rather than run

Hardware and licensed products that cannot reasonably be containerised:

| File | Source | Notes |
| --- | --- | --- |
| `paloalto_traffic.csv` | PAN-OS | fixed CSV column order per log type |
| `cisco_asa.log` | Cisco ASA | prose; field order differs per message ID |
| `fortigate.log` | FortiOS | natively key=value, needs no inference |
| `arcsight_cef.log` | ArcSight | published CEF spec |
| `qradar_leef.log` | QRadar | published LEEF 2.0 spec |
| `windows_security_evtx.xml` | Windows Security | repeated `<Data Name=…>` elements |

## `unknown/` — deliberately unmapped

No mapping exists for these, on purpose. They are what the discovery lane is
demonstrated against:

- `mikrotik_routeros.log` — free text with no stable token positions. Structure
  inference declines to guess, which is the honest outcome: this is the case a
  grammar-constrained local model would answer.
- `k8s_audit.json` — structured, so a proposal *is* produced, but it scores
  0.33 and goes to human review rather than activating.

Writing a mapping for either would defeat the purpose.

## `loghub/` — real published research corpora

**Not generated.** Downloaded from
[logpai/loghub](https://github.com/logpai/loghub): the 2,000-line samples for
HDFS, BGL and Thunderbird, each with its labelled `*_structured.csv` ground
truth.

These back the accuracy benchmark:

```bash
python tools/benchmark_loghub.py
```

Grouping Accuracy is measured against the published labels, so the number is
reproducible by anyone with the same files — including someone who does not
trust the system that produced it.

If you use these datasets, cite the LogHub paper:

> Jieming Zhu, Shilin He, Pinjia He, Jinyang Liu, Michael R. Lyu. *Loghub: A
> Large Collection of System Log Datasets for AI-driven Log Analytics.* ISSRE
> 2023.
